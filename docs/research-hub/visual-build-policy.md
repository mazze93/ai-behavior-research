# Visual build practice

For each substantial module/interface build, begin with a bounded inspiration pass and an inspectable visual guide before implementation. Default to at most three focused queries, three selected primary references and one direct lookup to resolve an inaccessible reference. Stop when the visual mechanism is specific enough to build. A font-selection refinement may use two focused font queries.

Record the sources and the original translation: layout, typography, palette, interaction, data meaning, empty/error states and mobile behavior. Art is inspiration for spatial reading and participation; it does not supply research evidence. Do not copy artwork, logos or restricted assets. Illustrations and fixtures must be marked and must not acquire result status through presentation.

Rust is the default for deterministic research cores and checked data transformations. TypeScript is the default for browser controls and interface contracts. Existing scientific reference implementations remain comparison oracles until parity is earned. Study-specific protocols and annotation gates remain distinct.

The canonical source home is mazze93/Research. Site changes are reviewed in mazze93/ai-behavior-research. AWA is the next study module; Bearing is the reusable tool. Keep source revisions, licensing boundaries, read scope and actual capability states with every adapter.

Compile browser controls with `npm run build:client --prefix apps/registry`; TypeScript source lives in `apps/registry/client/`, and generated browser assets live in `public/`. The guide is previewed by serving the repository root and opening `/docs/research-hub/visual-guide-authority-bearing.html`, so its relative self-hosted font/script paths resolve.
